# Using AI here

**Use it.** ChatGPT, Claude, Copilot, Gemini, whatever you have open. Nobody
here thinks less of you for it, and pretending otherwise would be strange —
this is how software gets written now.

There is one thing we ask.

## Understand what you send

If somebody asks *"what does this line do?"* about something in your pull
request, you should be able to answer. Not perfectly, not in jargon — but
you should know what it does and why it is there.

That is the whole policy.

## Why it is worth taking seriously

Reviewing a pull request takes a human about as long as writing one. On this
repository that human is a volunteer, doing it in the evening, for free.

When somebody sends generated code they have not read, that time goes
somewhere strange: the reviewer ends up debugging a solution to a problem
nobody had, and explaining it back to the person who sent it. Everybody
loses an hour and nothing improves.

When somebody sends generated code they *have* read — even if it is wrong —
the conversation is normal and useful. "This bit does X, but we need Y" gets
sorted out in two minutes.

The difference is not whether AI was involved. It is whether a person was.

## In practice

- Generate it, then **read it**. Delete the parts you do not need.
- Try it. If you cannot try it, say so in the pull request.
- If AI wrote something you do not follow, ask it to explain — or ask us.
  "I generated this and I am not sure about line 12" is a completely
  respectable thing to write in a pull request. It gets a good answer.
- Do not paste an AI's opinion into a discussion as if it were yours. Say
  where it came from.

## Today, specifically

Your contributor file should be about you. An AI does not know what you want
to build, and that line is the most interesting thing on your card.

## If you get it wrong

Nothing happens. Somebody will say "have a read of this and tell me what you
think it does", and you will. That is not a punishment, that is the job.
